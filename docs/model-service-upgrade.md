# 模型服务升级与恢复

本次升级新增 0012～0014 迁移（schema 7），不重写旧迁移。首次启动、开始监听前转换旧模型绑定；转换失败整批回滚，修复后可再次启动。迁移前通过 SQLite `VACUUM INTO` 生成包含 WAL 已提交内容的一致性备份，备份失败则停止升级。

## 配置处理

- 文本、图片、TTS 和已核对的七型号精确别名保留，生成显式接入和版本化定义。旧路径及历史地址处理被固化，新接入不自动补删版本前缀。已有定义、接入及任务快照保持原有版本。
- 设置中心「模型服务 → 旧视频配置升级记录」列出退出或版本未确认的绑定。新建、编辑、导入和历史重试均不能重新启用退出型号；不自动替换默认收费模型，也不修改画布原内容、连线、任务和资产。
- 无法判定的旧版本保持禁用、列为待处理；核对供应商文档后重新选择有效模型定义建立绑定。原绑定需显式移除，不靠子串匹配计费后缀或 Pro/Mini 变体。
- 旧任务只允许按快照查询、下载或本地放弃。缺快照时不猜目标、不重投；未知提交和下载失败保留恢复引用。本地放弃不等于远端取消。
- 未完成或仍有可恢复结果的任务会保护原渠道及凭据，阻止删除、禁用或替换密钥和请求头；不改变凭据的编辑仍允许。已成功、已确认失败或本地放弃后释放保护。退出绑定在没有恢复引用时清理；账号、共享渠道、密钥及用户自建接入由用户管理，不因退出单个型号自动删除。

## 离线恢复备份

备份位于 `<userData>/data/frame-loom.before-<旧迁移时间戳>-<备份时间戳>.sqlite`。它包含加密凭据，应像原数据库一样保管。应用不会自动删除备份。

1. 完全退出 Frame Loom 和其 engine。先另存当前 `data` 目录，保留项目文件、`media` 和 `secret-key.bin`。
2. 将当前 `frame-loom.sqlite`、`frame-loom.sqlite-wal`、`frame-loom.sqlite-shm` 移到另外的保留目录，避免混用旧 WAL。
3. 复制选定备份为 `data/frame-loom.sqlite`，保持原备份不动。继续使用原设备账号及原 `secret-key.bin`；仅复制数据库不能迁移系统加密主密钥。
4. 使用匹配该备份 schema 的应用版本恢复，或重新打开当前版本重跑升级。数据库恢复不回退项目文件格式和已发生的供应商计费。

本地测试覆盖临时旧库完整升级链、可读备份、SQL 迁移故障回滚、配置转换故障回滚、重复启动、共享凭据保护及旧任务查询。真实供应商账号、实际用户库和安装包升级验收在父计划 08 单独记录。
