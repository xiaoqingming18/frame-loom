# Agent Note: 未识别场标题时不能把整篇剧本吞入附录

Status: implemented

## Problem

用户粘贴《开学大审判：暑假作业失踪之谜》后立即得到 0 场、0 段、0 元素。本地复现：245 行、正文 0 段、前言为空、附录 5425 字。原文使用 `### 【第一场：人间炼狱早自习】`，场标题规则不接受外层方头括号；无场或幕时 lastBoundary 为 -1，自动附录规则把第一个 Markdown 标题及其后全文截走，违反[导入与 Markdown 视图](../../implemented/feature/2026-10-30-script-import-and-markdown-view.md)中「整份没有场或幕时全部按正文处理」的约定。

## Decision

- 自动附录仅在已找到场或幕之后启用；显式正文与附录标记继续优先生效。未知格式即使没有分场，也保留可编辑正文。
- 场标题解析仅对完整 `【第N场…】` 外壳去括号，复用已有中文序号与场标题解析，不把一般 `【画面】` 或普通 Markdown 标题扩展成场。
- 独立的时间、地点行保留为正文，不在本补丁中推断跨行属性。缺少同一行时间／内外的场仍为存疑，避免把叙事标题臆造为实际地点。尾声标题仍遵循现有附录规则。

## Alternatives considered

- 只补括号场标题：最小而且能识别当前五个场，但未知格式仍可能整篇归附录，因此同时修复无边界的回退。
- 把所有 Markdown 标题都当场：可以覆盖更多变体，但梗概、角色名单和改编说明会误成场，不采用。

## Testing

- 无场／幕的 Markdown 标题文档保留正文，不自动生成附录；显式附录标记仍有效。
- 方头括号内的第一场、第二场可识别，一般标签不识别为场；用户完整文本不再返回空正文。
- 新旧样例、Markdown 往返和 engine 转换回归通过；类型、lint 与笔记校验通过。

实际验证：用户完整原文由 0 段恢复为 5 场、136 段、7 处存疑，前言 275 字、附录 573 字；原文完整性检查通过。contracts 21 文件 326 项通过；engine 剧本 3 文件 19 项通过；contracts build、typecheck、改动文件 eslint 通过。没有把用户完整附件加入仓库，回归使用同格式的最小片段。

## Consequences

收益：未知格式不会仅因开头有 Markdown 标题就丢失整个正文；方头括号中文场标题进入正常的规则与模型分类路径。

多行时间地点暂不合并到场属性；缺少属性的场需要人工确认。真实模型未参与本次复现；修复只在重新构建并运行新代码后生效，已有导入需要重新导入。
