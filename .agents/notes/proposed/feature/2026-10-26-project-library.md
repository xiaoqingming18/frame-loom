# Agent Note: 项目库、创作页与项目本地存储

Status: proposed

## Problem

左栏「项目库」目前只有一个静态空状态页（`routes/projects.tsx`）。画布只能在「画布测试」页里用固定 id `lab` 打开，数据存在 engine 的 `canvas_documents` 表，媒体全部放在全局 `<userData>/media/`，没有项目这一层。用户要把「项目 → 创作页（画布）→ 项目资产」作为正式的创作组织方式：

- 项目库是项目卡片宫格，支持新建项目、搜索、切换排序；新建项目时填写项目名称和本地保存位置。
- 点击卡片进入项目详情页。详情页有「创作页」和「项目资产」两个 Tab：每个创作页是一张画布（例如「第一集」）；项目资产支持新建文件夹、上传文件、用文件夹组织文件，文件列表支持搜索和列表／宫格切换。
- 项目的本地存储方案要按「用户选择的目录」来设计，并给以后的云端功能留好接口。
- 画布模块与项目模块的关系要设计清楚；画布测试页随本次删除。
- UI/UX 对齐 `docs/design/project-library-light.html`（2026-10-26 收到的项目库快照，即用户下载目录中的 `project-light.html`）。只参考其中的项目库部分，公共外壳与图标风格保持现状，颜色只用 `theme.css` 中的 token（[UI 规范](../../../../docs/ui-guidelines.md)）。

用户已确定的取舍：

1. 项目文件夹保存清单、创作页和媒体，应用数据库只存可重建的本机状态。
2. 项目资产的根目录就是项目根目录。
3. 首期画布可以「从项目资产添加」素材，也可以把节点「保存到项目资产」；生成结果不自动归档到资产。
4. 删除项目时，在确认框里选择「仅从项目库移除」或「同时将项目文件夹移到回收站」，默认选后者。
5. 重命名项目只改显示名，不改文件夹名。
6. 名称冲突时报错，让用户改名，不自动加后缀。
7. 提供「打开已有项目」入口。
8. 侧栏显示全部项目，展开后列出该项目的全部创作页，点击进入对应画布。
9. 删除画布测试页。
10. 资产允许任意类型；单文件上限由本篇确定；同名上传自动改名。
11. 资产搜索范围是整个项目，结果显示所在路径。
12. 本次实现孤儿媒体清理。
13. 创作页按创建顺序排列；卡片封面取画布中最近生成或上传的图片，没有图片时显示纯色卡片。
14. 排序方式和列表／宫格偏好在重启后保留。

现状约束：

- engine 运行在 utilityProcess 里，不能调用 `shell`、`dialog` 或回收站；这些能力只有主进程有（[桌面壳](../../implemented/architecture/2026-10-24-desktop-shell.md)）。
- 画布包 `@frame-loom/canvas` 不能依赖 desktop、engine client 或路由，外部能力全部通过 `CanvasHost` 注入（[无限画布](../../implemented/feature/2026-10-25-infinite-canvas.md)）。
- 生产 CSP 的 `img-src`／`media-src` 只允许 `'self'` 和 `frame-media:`；`<img>` 和 `<video>` 不能带 Bearer 请求头。
- 现有媒体按 sha256 落在全局目录，元数据记录在 `media_files` 表；生成任务、对象存储和画布都只按哈希引用媒体（[模型管理](../../proposed/architecture/2026-10-24-model-management.md)）。
- 单实例锁保证同一时刻只有一个窗口；离开画布路由时会先完成保存，撤销历史随画布组件卸载而释放。
- 最小窗口 720×560，侧栏展开时主区宽度约 460px。

## Proposal

### 本轮实施边界

子计划 01–04 已完成，本轮授权实施 05（主进程能力与协议）和 06（项目库与详情页界面）。本篇在全部验收前保留 proposed。副本打开和名称冲突采用下文默认方案；本轮不删除 `canvas_documents`，不迁移画布测试文档。资产 Tab 内容与实际项目画布宿主分别由 07、08 接入；06 建立正式创作页路由并明确显示待接入状态，不复用固定 lab 文档。

主进程项目文件操作只接受注册项目 id 与可选资产相对路径；逐段拒绝符号链接／junction，解析 realpath 后检查边界，再读取清单核对 id。缺省 path 表示整个项目，资产调用必须显式传入非空 path；UI 分别构造这两种请求。协议在原始 URL 上校验，避免 URL 规范化隐藏穿越；仅转发白名单文件路由和 Range，不跟随重定向。偏好同步合并写入，避免主题与排序互相覆盖。项目默认保存目录由主进程创建，用户选择的其他目录仍需已存在。

03、04 沿用共享契约的 `destination`（移动目标目录）和 `path`（导出目标目录）字段，HTTP 搜索 `q` 映射到契约 `query`。媒体与资产共用项目文件访问检查及项目串行队列；内部方法在已持有队列时直接执行，避免嵌套等待。媒体解析服务由 projects 模块导出供生成和对象存储复用，不让项目模块反向依赖生成调度器。清理以磁盘页面和任务记录为准，读取失败时停止，不能将不可读视为无引用；活动会话避让手动与自动清理。

离线产物的待复制哈希单独记录在任务的 `staged_outputs_json`，复制成功后清除对应项。只凭「任务输出在项目里不存在」推断待复制可以少一个字段，但手动清理后会从仍为其他离线项目保留的全局文件反复恢复孤儿，因此不采用。新增迁移并将本机 schema_version 升至 3；产物落盘后、释放项目队列前同步登记输出与待复制状态，避免清理抢先。

01–06 已落地：contracts 提供项目、创作页、资产、偏好与目录 IPC 契约；engine 提供项目生命周期、媒体上传／补齐／解析、生成归属、离线暂存恢复、引用清理、资产操作及 Range 文件接口。页面保存返回 `{ revision, missing }`。0006 增加注册表、视图表与任务归属列，0007 增加待复制产物列表，落盘 schema_version 为 3。主进程完成偏好合并写入、目录／显示／回收站 IPC 与项目文件协议，renderer 提供项目库、详情创作页 Tab 和完整侧栏项目树。原生 label、radio、checkbox 配合现有 shadcn 组件实现表单，不增加依赖；项目清理先 dryRun 统计，确认后重新计算并执行。

05、06 验证：全仓 628 项测试（desktop 166）、typecheck、lint、构建通过；项目库与现有 smoke 的 5 项 Electron e2e 通过。真实创建、重命名、页面入口、Windows 回收站、排序／主题／位置跨重启、中文资产与项目媒体协议加载、键盘 Tabs 和弹窗关闭均有证据。明暗与最小窗口截图存入 `.cache/project-library/` 并逐图核对。资产 Tab、实际项目 CanvasHost、加固 exe 和全流程验收仍留给 07–09，不能将创作页入口占位描述为画布接入完成。

页面缓存保存 revision、mtime、size 和内容摘要，不缓存整份文档；每次仍检查磁盘内容，避免同步软件保留文件时间戳后读到旧 revision。只比较 mtime/size 可以减少磁盘读取，但无法识别同大小、同时间戳的外部改写，因此本期不采用。代价是每次页面读取／保存检查都读取并解析 JSON，受现有 8 MiB 文档上限约束。相同 revision 的外部改写也返回 409，必须重新加载；普通重试不会绕过冲突。

内部 `.frameloom` 路径同样检查符号链接／junction 与 realpath 边界；项目 id 串行队列之外，生命周期使用注册表队列避免跨项目同名并发。页面删除先移入回收区，清单写失败则移回；页面保存后的清单写失败保留页面，下次读取时修复封面与时间摘要。跨文件写入不构成事务，进程在删除页面与更新清单之间崩溃时，页面仍保留在回收区，需要人工恢复；本期无恢复界面。

验证：全仓 `pnpm test` 共 598 项通过（contracts 185、engine 186、canvas 91、desktop 136），全仓 typecheck 与 lint 通过。新增集成测试覆盖媒体补齐、元数据重建、全部版本／跨页面／poster／任务引用、会话避让、过期清理、离线恢复后不复活孤儿、旧任务清理、项目输入与对象存储读取、资产操作、限额、权限、junction、Range、附件与鉴权。无权限、空间不足和 8.3 解析边界使用注入；Windows 文件符号链接无权限时测试退化为 lstat 注入。未验证真实 8.3 别名、杀毒软件占用、非 NTFS 盘或断电恢复。总方案的 UI 和桌面 e2e 验收仍未完成。

资产上传完成后采用同卷硬链接原子发布，再删除临时链接；文件移动采用目标链接加移除源，目录仍 rename。普通 rename 的优势是支持更多文件系统，但可能覆盖检查后被外部程序创建的同名文件，因此文件发布与移动不采用覆盖式 rename。收益是不暴露半成品且不会覆盖同名文件；代价是需要支持硬链接的本地磁盘，跨卷或不支持的文件系统没有降级复制。路径检查与实际打开之间仍存在本地外部程序并发替换的窗口，本期不提供目录句柄隔离或文件系统监视。

### 概念与关系

| 概念 | 实体 | 说明 |
| --- | --- | --- |
| 项目 | 本地文件夹，加上项目库注册表中的一行 | 以文件夹为准，注册表只用于列表、搜索、排序和定位 |
| 创作页 | 项目内的一个页面文件 | 一页一张画布，按创建顺序排列 |
| 项目资产 | 项目根目录下的用户文件和文件夹 | 用户可以直接在资源管理器中管理 |
| 项目媒体 | `.frameloom/media/` 下按内容寻址的文件 | 画布节点引用的上传文件和生成产物 |

- 画布包不感知项目。desktop 按「项目 + 创作页」实现 `CanvasHost`，画布 id 就是创作页 id。
- 资产和媒体之间是复制关系，不是链接：资产导入画布时按内容复制进媒体库，画布产物「保存到项目资产」时导出为一个真实文件。用户在资源管理器中改名或删除资产，不会让画布断图；代价是同一个文件可能存两份。
- 生成任务记录所属的项目和创作页，产物直接写进项目媒体库。

### 项目文件夹格式

```text
<保存位置>\<项目名>\                    项目根目录，也是资产「全部文件」的根
  角色\张三.png                          用户资产
  .frameloom\                            内部数据，资产列表和搜索都不显示
    project.json
    pages\<pageId>.json
    media\<sha256>.<ext>
    trash\media\<sha256>.<ext>           孤儿媒体回收区，保留 30 天
    trash\pages\<pageId>-<时间戳>.json   已删除创作页，保留 30 天
    tmp\                                 上传与写入用的临时文件
```

`project.json`：

```json
{
  "format": "frame-loom-project",
  "formatVersion": 1,
  "id": "<uuid>",
  "name": "宣传片",
  "createdAt": "<ISO>",
  "updatedAt": "<ISO>",
  "pages": [
    { "id": "<uuid>", "name": "第一集", "createdAt": "<ISO>", "updatedAt": "<ISO>", "coverSha256": null }
  ]
}
```

页面文件：`{ "format": "frame-loom-page", "formatVersion": 1, "id", "revision", "document": CanvasDocument }`。`document` 沿用 contracts 的 `CanvasDocument`，上限和校验不变。

规则：

- schema 放在 `packages/contracts/src/projects.ts`。读取时保留未知的顶层字段，重写时原样写回，给以后的同步元数据留位置。
- `formatVersion` 高于当前支持的版本时，项目显示为「需要更新应用」，不能打开也不能写入；低于当前版本时，读取后迁移，下次写入时升级。
- `pages[]` 的顺序就是创建顺序。`updatedAt` 和 `coverSha256` 由 engine 在每次保存页面后计算并回写。封面取所有图片节点所有版本中 `createdAt` 最新的一张图片（生成或上传的都算），没有图片时为 `null`，界面显示纯色卡片。
- 写入流程：先写到 `.frameloom/tmp/`，`fsync` 后改名覆盖目标文件。Windows 上目标被占用（`EPERM`／`EBUSY`）时，以 50ms 起步退避重试，累计最多 2 秒；仍失败则返回 `PROJECT_WRITE_FAILED`，不破坏原文件。
- 同一项目的所有写操作（页面、清单、资产、媒体、清理）在 engine 内经过一个按项目 id 划分的串行队列。保存页面时先写页面文件，再写清单；两步之间崩溃会让清单摘要过时，下次读取页面时会修复。
- 页面 revision 写在页面文件里。engine 缓存「revision、mtime、size」，任何一项与磁盘不一致就重新读取，所以文件被外部改动（同步盘、另一台机器）时也能拿到真实 revision。不一致的保存返回 409 `PAGE_REVISION_CONFLICT`，renderer 沿用现有的「重新加载／导出当前画布 JSON」流程。
- `.frameloom` 在资源管理器中可见，本期不设置隐藏属性。

### 本机注册表与视图状态（engine SQLite）

- `projects`：`id`（uuid 主键）、`name`（缓存）、`root_path`（规范化后唯一，Windows 下不区分大小写）、`location_kind`（目前只有 `local`）、`remote_id`（为空，云端预留）、`created_at`、`updated_at`（缓存）、`added_at`、`last_opened_at`。注册表丢失后，可以通过「打开已有项目」逐个恢复。
- `page_views`：`project_id, page_id` 复合主键，`view_json`、`updated_at`。视口、小地图和连线显示按设备保存，不写进项目文件夹：平移画布不会改动项目文件，以后同步时也不会因此冲突。这一点翻转了[无限画布](../../implemented/feature/2026-10-25-infinite-canvas.md)中「视图与文档同行保存」的决定，原理由与新理由见下文备选方案。
- `generation_jobs` 增加可空的 `project_id`、`page_id` 列并建索引；`media_files` 继续作为全局元数据表，以 sha256 为键（元数据只由内容决定）。
- 删除 `canvas_documents` 表和 `modules/canvas`；画布测试数据不迁移（见待确认 4）。迁移文件新增，不重写已分发的迁移。

### 可用性与生命周期

- 列表接口逐个检查项目根目录，状态为 `available | missing | mismatch | unreadable | too_new`：
  - `missing`：目录或 `project.json` 不存在。
  - `mismatch`：文件夹里的项目 id 与注册表不一致。
  - `unreadable`：没有读取权限，或 JSON 损坏。
  - `too_new`：`formatVersion` 高于当前支持的版本。
  - 不可用的项目卡片显示名称（来自缓存）和状态说明，菜单提供「重新定位」和「从项目库移除」。
- 新建：
  - 名称去掉首尾空白后为 1–80 个字符。拒绝控制字符和 `<>:"/\|?*`，拒绝以点或空格结尾，拒绝 Windows 保留名（`CON`、`PRN`、`AUX`、`NUL`、`COM1`–`COM9`、`LPT1`–`LPT9`，比较时忽略大小写和扩展名）。
  - 项目名在项目库内唯一（比较时忽略大小写），冲突时报错。
  - 保存位置必须是已存在的绝对目录。`<保存位置>\<名称>` 已存在时报「该位置已存在同名文件夹，请修改项目名称」。项目根目录的完整路径不超过 200 个字符，给资产子目录留出 Windows 路径长度余量。
  - 用 `mkdir`（不带 `recursive`）创建项目根目录，保证这个目录是新建的。之后建立 `.frameloom` 结构并写入清单；任何一步失败都删除刚建的目录。
- 打开已有项目：用户选择包含 `.frameloom/project.json` 的文件夹。
  - id 未登记：直接登记。
  - id 已登记、原路径不可用：视为重新定位，更新路径。
  - id 已登记、原路径仍可用：多半是复制出来的文件夹，见待确认 1。
  - 项目名与库中其他项目重名时，见待确认 2。
- 重新定位：所选文件夹的项目 id 必须与该项目一致。
- 重命名：只写 `project.json` 的 `name` 和注册表缓存，文件夹不变。项目不可用时不能重命名。
- 删除：确认框列出项目名和路径，用单选项选择「同时将项目文件夹移到回收站（默认）」或「仅从项目库移除」。项目有未结束的生成任务时，提示「远端可能仍在运行并计费」，并提供「同时放弃这些任务」复选框，复用现有的 cancel。移到回收站由主进程执行；成功后 engine 删除注册行和对应的 `page_views`。
- 创作页：新建时只填名称（规则同项目名，在项目内唯一），初始为空文档，revision 1，创建后直接进入画布。支持重命名；删除时把页面文件移到 `.frameloom/trash/pages/`，提醒方式同项目删除，删除后在侧栏和列表中移除。
- 首页「选择项目」仍保持禁用，等创作功能开放后再接入。

### 媒体、生成与跨项目引用

- `MediaService` 增加按位置解析：`resolve(sha256, projectId?)` 依次查找项目媒体、项目回收区（找到就移回）、全局目录。元数据缺失时（例如项目从另一台机器拷来）就地探测并补写 `media_files`。现有文件头识别和 ffprobe 探测抽成 `describe(path)` 共用。
- 上传：`POST /projects/:id/media`（二进制流，沿用 256 MiB 上限），临时文件放在项目 `tmp/`，同卷改名进入 `media/`。
- 补齐：`POST /projects/:id/media/adopt { sha256[] }`。依次从全局目录、其他可用项目、本项目回收区复制，返回仍缺失的哈希。画布在粘贴和导入 JSON 时先调用它；页面保存时 engine 再检查一次，并对缺失项尝试补齐。仍缺失也照常保存，不阻止用户保存；节点显示「素材缺失」占位。
- 生成：`GenerationRequest` 增加可选的 `projectId`、`pageId`，由画布宿主在提交前填入。创建任务时校验项目可用；输入素材按项目解析；产物优先写入项目 `media/`。项目暂时不可用时，产物落在全局目录作为暂存。之后项目恢复可用（列表检查或打开时），engine 把暂存产物复制进项目；画布打开后照常补写版本。对象存储上传改用同一个解析器，不再硬编码全局路径。
- 显示：主进程注册只读协议 `frame-project://<projectId>/media/<sha256>` 和 `frame-project://<projectId>/assets/<编码后的相对路径>`，转发到 engine 的 `GET /projects/:id/files/...`，携带 Bearer 并透传 `Range`。路径校验只在 engine 一处：
  - 先规范化相对路径。拒绝 `..`、绝对路径、盘符、`\0`、Windows 设备名，以及任何以 `.frameloom` 开头的资产路径。
  - `realpath` 结果必须仍在项目根目录内；拒绝符号链接和 junction（`lstat` 逐段检查）。
  - 文件交给 Express `sendFile`（支持 Range），并设置 `X-Content-Type-Options: nosniff`。只把图片、视频、音频声明为可内联的 MIME，其他类型一律 `application/octet-stream` 并附带 `Content-Disposition: attachment`。
  - 生产 CSP 的 `img-src`、`media-src` 加入 `frame-project:`。成功响应的 CORS 只允许当前可信 renderer 源，视频抽帧照常可用。
- 画布不再使用 `frame-media://`。该协议和全局媒体目录继续服务于暂存和旧任务记录，是否删除在[模型管理](../../proposed/architecture/2026-10-24-model-management.md)验收后再评估。

### 孤儿媒体清理

- 引用集合（某个项目）：
  - 所有页面文件中图片和视频节点全部版本的 `sha256` 与 `posterSha256`；
  - 该项目所有未结束任务的输入与产物；
  - 被任何页面 `pendingJobIds` 引用的任务的输入与产物，包括已成功但尚未写回的任务。
  - 以页面文件为准，不读取撤销历史。
- 自动清理：离开该项目的画布路由（保存完成后）、删除创作页后、打开项目详情时各触发一次，在项目串行队列中执行。不在引用集合中的 `media/` 文件移入 `trash/media/`；回收区中超过 30 天的文件、`tmp/` 中超过 1 小时的残留文件被永久删除。画布打开期间，该项目不执行清理（宿主进入和离开画布时调用 `POST /projects/:id/sessions/open|close`，engine 重启后会话清零），保证内存中的撤销历史不会引用到已移走的文件；即使发生意外，`resolve` 和补齐也会从回收区找回。
- 手动清理：项目卡片菜单中的「清理未使用媒体」先统计可回收的数量和体积，确认后立即执行清理并清空回收区，然后报告释放的空间。
- 全局目录：engine 启动时清理全局 `media/`，删除不被以下任何一项引用的文件：未结束的任务；项目可用但尚未复制产物的任务；所属项目不可用、产物仍在暂存的任务。画布测试遗留的媒体和无项目的旧任务产物会被删除（任务记录保留）。

### 项目资产

- 接口（路径都是相对项目根目录、使用 `/` 分隔的字符串，engine 按上文规则校验）：

  | 能力 | 接口 |
  | --- | --- |
  | 列目录 | `GET /projects/:id/assets?path=` → 名称、类型（目录／文件）、大小、修改时间、媒体类别（image／video／audio／other） |
  | 搜索 | `GET /projects/:id/assets/search?q=` → 全项目递归、名称不区分大小写子串匹配，结果带所在目录；最多 500 条并提示「结果过多，请细化关键词」；跳过 `.frameloom`、链接和无权限目录 |
  | 新建文件夹 | `POST /projects/:id/assets/folders { path, name }`，同名时报错 |
  | 上传 | `POST /projects/:id/assets/files?path=&name=`，二进制流，单文件上限 4 GiB；先用 `statfs` 检查剩余空间，写入 `tmp/` 后硬链接发布并移除临时链接，同名时按「名称 (2).ext」递增；返回最终名称 |
  | 重命名 | `PATCH /projects/:id/assets { path, name }`，同名时报错 |
  | 移动 | `POST /projects/:id/assets/move { path, toFolder }`，同名时报错，不能移入自身或子目录 |
  | 从资产导入媒体 | `POST /projects/:id/media/from-asset { path }` → MediaFile，仅限图片和视频 |
  | 保存到资产 | `POST /projects/:id/assets/from-media { sha256, folder, name }`，同名时自动改名 |

- 删除资产（文件或文件夹）进入系统回收站，由主进程执行，确认框写明「将移到回收站」。
- 上传队列在 renderer：最多 2 个并发，显示进度，可以取消和重试。资源管理器拖入的文件夹本期跳过，并提示「暂不支持上传文件夹」。离开项目详情页时，如果还有未完成的上传，先确认「离开将取消剩余上传」。
- 预览：宫格模式和列表图标中，图片和视频直接读原文件显示缩略图（`loading="lazy"`；视频只显示首帧，不自动播放）。点击图片、视频、音频打开预览对话框，其他类型不预览。
- 文件被外部修改后不自动监听：通过刷新按钮或窗口重新获得焦点时重新查询。`shortcut: 不做文件系统监听，用户反馈外部变更不同步时再引入 fs.watch`。
- 不提供「用默认程序打开」：`shell.openPath` 会直接执行 `.exe` 一类文件。只提供「在资源管理器中显示」。

### 主进程能力与偏好

可信 IPC 与现有 IPC 一样校验调用方，参数用 contracts 校验：

- `dialog:pick-directory { defaultPath? }`：原生选择目录，返回路径或 `null`。
- `project:reveal { projectId, path? }`、`project:trash { projectId, path? }`：主进程用自己持有的 engine 连接查询项目根目录，按与 engine 相同的规则解析路径，再确认 `.frameloom/project.json` 的 id 与 `projectId` 一致，然后调用 `shell.showItemInFolder` 或 `shell.trashItem`。删除资产时 `path` 不能为空，也不能指向 `.frameloom`；删除项目时 `path` 为空。renderer never 直接传入任意路径给回收站。
- `preferences.json` 仍为 `version: 1`，新增可选字段 `projectLocation`、`projectSort`（`updated | created | name`）、`assetView`（`list | grid`）。写入改为读取、合并、原子替换，不能再只写主题字段。renderer 通过 `preferences:get`／`preferences:set` 读写，并通过 `lib/desktop-bridge.ts` 访问。
- 默认保存位置：`<文档>\Frame Loom\Projects`，首次使用时创建；用户选择过其他位置后，记住上次使用的位置。

路径信任边界：renderer 可以把保存位置或已有项目路径交给 engine。engine 只会在保存位置下新建一个原本不存在的子目录；只登记已经包含 `project.json` 的目录；所有后续文件操作都限制在已登记项目的根目录内，engine never 写出项目根目录。

### 云端预留

- 项目 id 使用 UUID；注册表保留 `location_kind`、`remote_id`；弹窗标题「新建本地项目」，以后可以并列「新建云端项目」。

### 待确认

以下是本篇的默认方案，评审时可以改：

1. 打开已有项目时，若项目 id 已登记且原路径仍可用（通常是复制出来的文件夹），提示「该项目已在项目库中」，并提供「作为副本打开」：写入新 id，名称加「副本」后缀（重名则报错让用户改名）。
2. 项目名唯一性在新建和重命名时强制执行；打开已有项目时如果与库中其他项目重名，要求先改一个显示名才能登记。
3. 删除资产进入系统回收站；删除创作页移入项目内的 `.frameloom/trash/pages/`，保留 30 天，本期不提供恢复界面。
4. 画布测试的数据（`lab` 文档及其全局媒体）不迁移，随表删除和全局清理一起移除；需要保留的，在升级前先用画布右键菜单导出 JSON。

## Alternatives considered

- **页面和媒体仍放在应用数据库，项目文件夹只放资产**：最强的理由是改动小，可以沿用 `canvas_documents` 表、事务和现有的 revision 实现，没有文件锁和外部改动的问题。没有采用：项目离开这台机器就打不开，备份需要同时拷贝数据库和文件夹；用户已选择以项目文件夹为准，以便整体拷贝和以后同步。
- **每个项目一个 SQLite 文件（`.frameloom/project.sqlite`）**：最强的理由是保留事务和查询能力，页面写入是原子的，单个大文档也不用整份重写。没有采用：同步盘和云同步复制正在写的 SQLite（尤其是 WAL 文件）容易损坏，冲突时也无法按页面合并；单页 8 MiB 上限内，JSON 整份写入的成本可以接受，而且便于排查和导出。
- **资产单独放在 `资产\` 子目录**：最强的理由是项目根目录更干净，内部数据和用户文件边界清楚。没有采用：用户选择以项目根目录作为资产根目录，与 Obsidian 库的习惯一致，资源管理器里看到的就是资产。
- **画布直接引用资产文件路径，不复制**：最强的理由是不会重复存储，修改资产后画布同步更新。没有采用：用户在资源管理器中改名、移动或删除资产后，画布会断图；生成参考和撤销历史都依赖内容不变，按哈希复制能保证这一点。
- **视图状态继续与文档一起写进项目文件夹**（无限画布原决定）：最强的理由是换机器后视口不变，原篇还以此避开 localStorage 在开发和生产环境各存一份的问题。没有采用：平移和缩放会频繁改写项目文件，触发同步盘上传，以后多设备编辑时也会产生无意义的冲突；视图状态改存 engine SQLite，开发和生产仍然只有一份，原篇反对 localStorage 的理由依然成立。
- **主进程直接从磁盘读取项目文件（像 `frame-media://` 那样）**：最强的理由是少一次本机 HTTP 转发，视频拖动更快。没有采用：主进程需要另存一份项目根目录映射，并重复实现路径校验；所有路径规则只放在 engine 一处更不容易出错，转发的代价是本机回环上的一跳。
- **由主进程签发不透明的目录凭据，renderer 不接触路径**：最强的理由是即使 renderer 被注入脚本，也无法让 engine 碰到用户没有选择的目录。没有采用：engine 只会新建原本不存在的子目录、只登记已含 `project.json` 的目录，并且只在已登记项目内写入，被注入的 renderer 能做的事已经受限；凭据方案要在主进程和 engine 之间增加状态同步。
- **重命名项目时一并重命名文件夹**：最强的理由是显示名和文件夹名保持一致。没有采用：用户选择只改显示名，避免文件夹被同步盘、资源管理器或其他程序占用时改名失败，也不会让外部快捷方式失效。
- **同名时自动加后缀**（项目、创作页、文件夹）：最强的理由是操作不被打断。没有采用：用户要求名称冲突时报错改名；只有上传文件按用户决定自动改名。
- **立即删除孤儿媒体，不设回收区**：最强的理由是实现简单，空间立刻释放。没有采用：粘贴旧剪贴板内容、导入 JSON、外部同步回来的旧页面都可能再次引用这些哈希，30 天回收区可以自动找回；手动清理提供立即释放空间的途径。
- **监听资产目录（`fs.watch`）实时刷新**：最强的理由是外部改动立即可见。没有采用：Windows 上递归监听大目录有事件风暴和句柄占用问题，同步盘和网络盘的行为也不一致；首期用手动刷新和窗口聚焦时重新查询。

## Acceptance criteria

自动测试：

1. contracts：项目清单、页面文件、资产与偏好 schema；名称规则覆盖非法字符、保留名、尾随点或空格、长度；未知字段保留；`formatVersion` 过高时拒绝。
2. engine 集成测试（真实 SQLite 与临时目录）：
   - 新建时同名文件夹报错，失败后回滚，路径长度上限生效；
   - 打开、重新定位、mismatch／missing／too_new 状态；
   - 页面 revision 409，外部修改文件后能检测到；
   - 原子写入在目标被占用时重试；
   - 路径穿越、`.frameloom`、junction 被拒绝；
   - 上传大小、剩余空间检查和同名自动改名；
   - 搜索跳过内部目录且有结果上限；
   - 补齐与回收区找回；
   - 孤儿清理保护三类引用，回收区按期限删除，全局清理不删除暂存产物；
   - 生成产物写入项目，项目不可用时先暂存、恢复后再复制。
3. desktop 单测：新 IPC 拒绝不可信调用方和非法参数；`project:trash` 拒绝 id 不匹配和内部路径；偏好合并写入不丢失主题；`frame-project` 转发透传 Range，并拒绝非法 URL。
4. 画布包：粘贴和导入 JSON 时调用 adopt；素材缺失占位；资产相关菜单只在宿主提供 `assets` 时显示。
5. 桌面 e2e：
   - 新建项目和创作页后在画布中上传图片；重启后项目、页面、画布内容和视口都保留；
   - 侧栏展开可进入页面；
   - 资产上传、新建文件夹、移动、搜索、切换布局；
   - 从资产添加到画布，以及保存到资产；
   - 删除项目后移入回收站（e2e 用临时目录并检查目录消失）；
   - 原有画布 e2e 改走项目路径，全部通过。

人工验收（开发环境与加固 exe，明暗两种模式都检查）：

1. 项目库、排序菜单、卡片菜单、新建对话框、详情两个 Tab、资产页与快照布局一致，颜色全部来自 token。
2. 720×560 下工具栏能换行，卡片单列，不溢出；键盘可以操作卡片、菜单和对话框，焦点可见。
3. 在资源管理器中改名或删除资产后刷新，列表同步，画布不断图；拔出 U 盘或改名项目文件夹后，卡片显示不可用，并能重新定位。
4. 拷贝项目文件夹到另一路径后用「打开已有项目」能正常打开，媒体显示正常。

## Risks

- **文件系统不可靠**：同步盘、杀毒软件和网络盘可能长时间锁文件或延迟写入，重试 2 秒后仍会失败；失败时画布保留内容并显示保存失败，用户可以导出 JSON。
- **整份 JSON 写入**：大页面每次保存都重写最多 8 MiB，同步盘会整份上传；如果实际体验明显变差，再评估增量格式，届时需要升级 `formatVersion`。
- **重复存储**：资产和媒体之间是复制关系，大视频在两边各存一份；清理只处理媒体库，不碰资产。
- **原图缩略图**：资产宫格直接解码原图，大量 4K 图片可能占用较多内存，沿用画布缩略图服务的延后决定。
- **本地转发**：视频经过主进程转发 engine，拖动进度会多一跳；如果出现卡顿，再评估主进程直读并共享校验函数。
- **破坏性迁移**：删除 `canvas_documents` 会丢弃画布测试数据（见待确认 4）；迁移一旦分发就不重写，回退需要新增反向迁移，无法找回已删除的数据。
- **路径边界**：junction、8.3 短文件名、大小写和 Unicode 规范化都可能绕过简单的前缀比较，必须基于 `realpath` 比较并配合测试；未覆盖的文件系统（如 ReFS、网络共享）只做到尽力而为。
- **回滚**：各子计划可以单独回退；项目文件格式一旦有用户数据，就只能向前迁移。
