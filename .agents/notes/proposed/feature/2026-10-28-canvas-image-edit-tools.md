# Agent Note: 画布图片节点多角度、重打光与表情编辑

Status: proposed

## Problem

Frame Loom 的图片节点已有图片版本、参考输入、持久化生成任务、任务恢复和结果写回，但没有基于当前图片版本执行多角度、重打光和局部表情编辑的入口。普通图片生成不会自动把自身活动版本作为输入；三个功能也需要不同的提示词交互，其中表情编辑还依赖人脸定位、蒙版、局部合成与中间工件恢复。只增加工具栏按钮或复用普通生成面板，无法保证编辑目标、收费任务、最终整图和原图版本一致。

用户要求 1:1 复刻 BeefTV 的三项功能，并确认该项目属于其工作室，允许内部复用其代码和资源；本需求不做来源、授权或源码许可调查。用户进一步确认：采用 Frame Loom 主题与组件；表情工件和最终合成进入 engine；只为本地可信资源做必要的 CSP 调整；模型不兼容时让用户显式选择；关闭时中止未提交准备，已提交任务固定使用提交时的源图快照；打光模板只在本次面板实例有效；不引入全局画布风格系统；测试按子计划针对新增风险设计，控制编码 Agent Token 与重复验收成本。

## Proposal

### 产品行为

三项操作均以图片节点当前活动版本为源，绝不覆盖源节点。确认后在源节点右侧创建一个图片子节点并连线，结果和编辑参数可追溯到精确的源 SHA-256。每项操作固定单张输出。模型选择默认沿用源节点模型；若其有效能力不满足操作要求，工具内要求用户显式选择兼容模型，不静默切换。

- **多角度**：复刻摄像头／天空盒预览，水平环绕 −180°～180°、俯仰 −60°～60°、景别 1～10（默认 4.8）、标准／广角；默认水平 45°、俯仰 0°、标准镜头。六个预设仅改水平和俯仰，保留景别与镜头。CSS 3D 仅作交互示意，生成时把角度语义转入提示词；确认即提交一个以源图为唯一参考的编辑任务。
- **重打光**：复刻 Canvas 2D 光源球、方向、亮度、轮廓光、光色、八个风格预设、智能描述和可编辑提示词模板。默认前向主光、亮度 50、白光、无轮廓光、无风格、智能模式开启。风格预设只切换风格文字，不联动其他光参数。确认时创建待生成子节点并打开已有通用生成输入框，用户检查／修改提示词后再发送。模板在面板打开期间即时生效，关闭模板编辑不撤销；关闭打光面板后恢复默认。
- **表情**：复刻本地人脸检测、多脸选择、手动框选、25 个情绪预设、情绪盘及 Morph Target 头部预览。每次只处理当前选择的一个角色；角色之间不批量、不串行合成，用户需要在上一产物上再次操作其他角色。默认情绪为中性克制。engine 生成编辑裁切、身份参考图与透明椭圆蒙版，调用兼容图片编辑模型；蒙版不支持时沿用原版降级并提示。最终结果必须在 engine 以源图为底按原版羽化和颜色校正规则合成，完成后才作为最终整图入库／写回。

### 跨层契约与生命周期

在 `packages/contracts` 增加严格、版本化的图片编辑配方及操作能力，和普通 `GenerationRequest.params` 分离。配方需含来源节点／SHA-256、编辑类型及参数；表情额外含目标脸框、编辑区域、蒙版模式和中间处理状态。前端与 engine 使用同一能力规则，engine 对参考图数、协议、蒙版支持和输入边界再次校验。

源图及生成前工件以媒体哈希引用保存，不在画布 JSON 或任务快照中塞 Base64。将新增引用接入项目媒体清理保护、恢复和跨项目收养。未提交的表情准备支持 AbortSignal；源图活动版本变化使选区失效并要求重新确认。任务提交后冻结源图与参数快照，后续面板关闭或节点换版本不改变任务。engine 中间处理可重试，不得因后处理失败重发收费生成；最终整图写回必须幂等。

界面放在 `packages/canvas` 图片节点工具区，宿主仍经注入 API 提供项目媒体与任务能力。预览、Worker、WASM 与 three.js 资源按需加载，使用 Frame Loom 主题 token、shadcn、lucide 与键盘可访问交互。生产 CSP 仅增加实际必需的本地 worker／资源许可，不开放任意远端脚本或连接。

### 分阶段实施与成本控制

父计划拆为五个同级子计划：01 共享编辑契约与媒体引用；02 engine 表情工件、模型适配与可恢复合成；03 图片入口、多角度和重打光；04 人脸工作区、检测与 3D 预览；05 端到端联调及唯一一次加固目录版验收。依赖顺序为 01 → 02／03／04 → 05。

每个子计划仅增加对应风险的定向测试，复用现有 contracts、engine、canvas 与 desktop 测试工具。测试优先使用少量、可解释的小型像素夹具和模拟供应商；人脸检测与 WebGL 不放进单元测试。05 集中运行一次全仓质量门禁和一次加固目录版，并合并截图／人工检查；不重复通用任务恢复矩阵、无差别全分辨率／显卡矩阵、NSIS 安装卸载、收费供应商调用或逐控件快照。后续质量门禁和原生验收只能在实际执行后记为通过。

## Alternatives considered

- **浏览器完成表情合成**：最强理由是沿用 BeefTV 的 Canvas 2D 实现，可少改 engine，也无需新增 engine 图像处理依赖。不选：Frame Loom 的生成任务在画布关闭后仍持久运行；renderer 卸载会令最终整图加工丢失或把裁切图错误报告为最终产物。将中间状态交给 engine 可随任务恢复，但增加 engine 图像处理、打包和恢复测试成本。
- **把三项功能实现为普通提示词模板**：最强理由是复用现有输入框和图片编辑协议，改动与测试成本最低。不选：多角度和重打光的参数化预览、打光的二次确认，以及表情的目标定位、身份参考和本地合成均无法保留；会把功能降级为非 1:1 的提示词快捷方式。
- **把编辑参数写进普通模型 `params`**：最强理由是可直接复用现有通用参数控件与请求字段。不选：该对象由档案白名单解释并用于供应商参数映射；角度、人脸框和工件状态不是通用模型参数，混入会让校验、适配器和模型切换产生错误语义。采用独立的版本化编辑配方。
- **按项目或用户保存打光模板**：最强理由是避免重复编辑并在多个画布复用。不选：用户确认复刻 BeefTV 当前“仅本次面板实例内存”的行为；持久化会新增设置／项目格式和覆盖语义，超出确认范围。

## Acceptance criteria

- 三个入口只对有效图片节点呈现；每项基于当前活动版本，不覆盖源节点，子节点和来源连线合成一步撤销；节点／任务保存精确源哈希和编辑参数。
- 多角度的范围、默认值、预设保留行为、CSS 3D 预览、提示词和立即提交符合调研源码；光源球和全部打光选项正确映射到提示词，打光保留二次发送及会话模板语义。
- 表情零检测、检测失败和多脸均可走当前单人选择／手动框选路径；25 个情绪点、默认值与 Blendshape 预览符合原版；局部最终合成以源图为底且最终媒体尺寸等于源图。
- 模型能力由共享规则表达并由 engine 强制；不兼容模型要求显式选择；无蒙版能力按确认的降级路径提示。
- 关闭／源图变化中止未提交准备；在途任务只处理冻结快照；engine 后处理恢复不会重复供应商提交；成功写回只有最终整图且无重复版本。
- 媒体清理、项目恢复及跨项目收养保护所有仍需使用的源图和工件；旧画布数据不因新契约失效。
- 新增功能通过计划中各自的定向测试。全仓门禁、明暗／720×560 实际界面和加固目录版本地资源加载在最后只执行一次并留下证据；未调用收费供应商，不声称生成质量已真实验证。

## Risks

- 现有图片媒体服务识别格式和尺寸，但未必具备可部署在 engine 的像素处理能力；实施时需用小型确定性夹具确认选用的处理 API，并核对 Windows 目录包原生依赖。若必须新增依赖或更改已确认的处理边界，回到用户确认，不静默降级。
- 图片编辑协议并非能力同质：OpenAI、Gemini、Ark 的参考图数量、编辑路径和蒙版能力可能不同。应通过精确模型有效能力决定可用性；模拟请求证明不了指定中转站线上实现。
- 高分辨率图像的裁切、颜色像素处理和 WebGL 会产生显著内存及 GPU 负载；上限通过一次小规模目标设备实测确定，超限需给出可操作错误，不承诺无上限。
- 加固 CSP 的 Worker、WASM 和模型资源加载路径需实测。不得为通过验收而添加远端脚本源、`blob:` 任意脚本执行或宽泛 `connect-src`。
- 多角度提示词生成不保证模型能准确还原不可见背面；预览不是重建质量承诺。真实美术效果需未来获得明确型号和费用授权后单独验收。

收益是保持三种不同创作节奏并让表情最终结果具有本地像素边界保障；代价是跨契约、engine、canvas、宿主、持久媒体和 CSP 的改动，以及维护图像处理恢复和 WebGL／Worker 资源路径。
