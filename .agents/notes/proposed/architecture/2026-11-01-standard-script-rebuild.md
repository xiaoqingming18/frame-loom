# Agent Note: 标准剧本、项目 SQLite 与模型全文解析重构

Status: proposed

## Problem

用户重新确定剧本规范，要求从「扁平类型段落＋规则识别＋可选模型分类」改成「元信息＋场次＋动作／对白」，整集原文由文本模型解析成标准 JSON，编辑区域及场次大纲严格对齐 `docs/design/juben.html`。旧剧集、剧本、设定、导入原文和相关回收内容全部清除，不做内容迁移。人物和地点进入项目设定库，用户可以持续完善资料。

当前实现与目标有实质差异：剧集摘要在 `.frameloom/project.json`，剧本在 `.frameloom/scripts/<episodeId>.json`，设定在 `.frameloom/story.json`；应用级 SQLite 保存项目登记等本机信息。直接改界面或新增 SQLite 表但继续读写旧文件，会留下两套权威数据。现有编辑器、引用定位、项目树、页面所属剧集和偏好均依赖旧契约，需要一起闭合修改范围。

本篇记录 2026-11-01 对话中用户已经确定的产品决定。用户授权全部子计划开发、测试与验收；代码已实施，自动化和开发版 Electron 流程已验证，当前仍处于最终验收。`proposed` 状态保留到验收完成，不表示以下决定可由实施 Agent 重新选择。破坏性清理只在可丢弃临时项目验证。

engine 的有界 LLM 调用／本地项目存储另补 8 项通过，核心与直接依赖共 56 项。最终目录包重建后的首轮导入请求触发五秒 HTTP 超时；失败日志保留，增加无凭据请求时序诊断后同一构建物复跑 N02 通过，首次超时底层原因仍未确认。没有调大生产请求超时或放宽 fuses。烟测清除旧成功记录并在失败时写诊断，最终结果与已知风险汇总于 `.cache/standard-script-rebuild/acceptance.md`。

目录版烟测通过 `apps/desktop/e2e/script-packaged.smoke.ts` 正常启动加固后的可执行文件，以临时本机端口连接渲染进程，测试结束关闭应用和端口；不修改生产 fuses、不使用主进程调试注入。直接使用 `_electron.launch` 最方便复用开发版驱动，但 [Playwright 官方说明](https://playwright.dev/docs/api/class-electron#known-issues)其依赖的 `EnableNodeCliInspectArguments` fuse 不能关闭，与当前生产加固策略冲突，故不采用。渲染进程连接使用 [Electron 支持的命令行调试端口](https://www.electronjs.org/docs/latest/api/command-line-switches#--remote-debugging-portport)，仅由显式烟测命令启动。网络资料核对时间为 2026-11-02，后续版本可能变化。

## Proposal

### 约束编号与决定权限

| 编号 | 已确认的不可偏离约束                                                                                                            |
| ---- | ------------------------------------------------------------------------------------------------------------------------------- |
| R01  | 项目级 SQLite，数据库随项目目录保存；标准 JSON 是业务文档／模型输出格式，SQLite 分表持久化。                                    |
| R02  | 旧剧集记录、剧本文字、全部设定（含手工）、导入原文和剧本相关回收内容清除；不迁移旧内容。                                        |
| R03  | 画布、媒体、资产、项目基础信息、模型配置不删除；旧剧集的画布归属解除为未分集。                                                  |
| R04  | JSON 增加 `meta.genre`；仅保留单集时长，删除时长预估和 `duration_text` 的独立存储。                                             |
| R05  | 剧名取项目名，类型取项目题材，画风取项目共享设定；集号、标题、单集时长取剧集信息，编辑器对应位置只读。模型不得覆盖这些值。      |
| R06  | 严格只支持场次以及 action／dialogue；移除旧段落分类、Markdown 双向编辑、前言附录、制作提示独立类型等旧能力。                    |
| R07  | 严格复刻设计快照的编辑区与大纲布局／交互；仅页面工具栏收敛为「重新导入」「保存」。                                              |
| R08  | 编辑区保留添加场次、添加动作／对白、移动、删除、动作／对白切换、内外／日夜切换；大纲保留定位和滚动联动。                        |
| R09  | 场号只读，由当前集号和场序生成；场次／内容内部 ID 在编辑、移动、重排、保存和重开后稳定。                                        |
| R10  | 整集解析由文本模型完成，不允许旧规则解析兜底；支持长文多次调用，不摘要、不截断。                                                |
| R11  | 人物来自出场名单、对白说话人及动作中出现的人物；地点来自场次 location。只在当前项目去重，主名／别名精确复用，模糊关系人工合并。 |
| R12  | 自动新增设定为待确认；不覆盖手工资料；设定改名不自动改写剧本文字；用户完善的设定不因删除剧本引用而自动删除。                    |
| R13  | 人物支持姓名、年龄、性别、外貌锚点、性格标签、标志动作、标志道具；地点采用本篇字段；道具／服装分类保留，标志道具先存文字。      |
| R14  | 失败、取消、容量不足、结构／原文校验失败不得替换当前有效剧本或留下半份设定；修订冲突不可静默覆盖。                              |
| R15  | 只做本次受影响链路的必要测试；不以全仓测试、全模型协议测试或完整 NSIS 安装验收作为本次默认门禁。                                |

实施 Agent 可以决定文件拆分、函数命名、索引和内部错误类型等实现细节，但不得改变 R01—R15。遇到需要改变数据归属、清除范围、输出格式、模型路线、UI 操作或验收强度的情况，先记录偏差和证据，再向用户提出具体变更；不能以「顺便优化」「旧测试要求」自行扩展或回退方案。测试失败应修复实现，不能降低这些约束来获得通过。

### 唯一数据来源与标准文档

- `.frameloom/project.json` 继续持有项目身份、名称、profile、创作页摘要、标签等已有项目内容；不将画布、媒体或模型服务迁入项目数据库。
- 类型复用 `profile.genres`，标准 JSON 的 `genre` 由题材按 `/` 连接，不另建可独立编辑的类型字符串。新增项目级画风字段；未填时为空，模型不猜补。
- `.frameloom/project.sqlite` 持有新剧集、剧本、设定及解析任务。剧集只在数据库持有，不在清单另存可编辑的 `episodes[]`。为兼容现有调用者，项目读取响应可聚合数据库剧集，但磁盘清单契约和 HTTP 聚合契约必须区分。
- `duration_sec` 使用非负整数秒，0 表示未填写，界面显示「未填写」，不根据字数推估。剧集信息入口负责编辑。画风和时长的新增表单不强迫用户补齐无关的内容形式、媒介、画幅。
- 文档自己的 `core_conflict`、`hook_start`、`hook_end` 在剧本中编辑；其余上述只读元信息在读取／导出时由最新项目和剧集信息投影。保存入口不能反向更新项目设定。
- 对外标准 JSON 字段为下例，禁止恢复 `blocks`、`preface`、`appendix`、`review`、`duration_text` 或第三种 beat 类型。编辑 API 可以使用外层 revision、任务状态和内部 ID，但它们不能混进模型正文格式。

```json
{
  "meta": {
    "series": "剧名",
    "episode": 1,
    "title": "本集标题",
    "genre": "都市 / 悬疑",
    "duration_sec": 780,
    "style": "画风描述",
    "core_conflict": "一句话核心冲突",
    "hook_start": "开场钩子",
    "hook_end": "结尾钩子"
  },
  "scenes": [
    {
      "scene_id": "1-1",
      "location": "便利店",
      "time_of_day": "夜",
      "interior": true,
      "characters": ["林夏", "西装男"],
      "atmosphere": "安静，灯光冰冷",
      "beats": [
        { "type": "action", "content": "△ 林夏看向门口。" },
        { "type": "dialogue", "speaker": "林夏", "emotion": "疑惑", "line": "您认识我？" }
      ]
    }
  ]
}
```

`time_of_day` 只允许「日」「夜」，`interior` 只允许布尔值。动作内容标准化为至多一个起始 `△ `，编辑器绘制一次标记，不能往返累加。emotion 允许空文本，台词标点不自动改写。新建未导入剧本允许空 scenes，添加场次创建可编辑空场；导入成功结果必须至少有一场，空内容行允许保留为草稿。

内部场 ID／内容 ID 由程序产生，展示 `scene_id` 不承担引用职责。移场、改单集号只改变排序和投影；重导入是整集替换，可产生新内部 ID，不能声称跨重导入保持身份。设定和动作中的文字保留用户用词，内部关联另外保存。

### 项目数据库边界

沿用现有 `better-sqlite3`、Drizzle 与 Zod，不为本次增加 ORM、编辑器或状态库。建议表及其必须表达的关系：

| 表                    | 必须表达的数据／约束                                                                          |
| --------------------- | --------------------------------------------------------------------------------------------- |
| `script_store_meta`   | 数据库 schema 版本、所属项目 ID、旧格式清理阶段／完成标记。                                   |
| `episodes`            | 稳定 ID、唯一集号、标题、单集时长、文档 revision、核心冲突和首尾钩子、时间戳。                |
| `script_scenes`       | 稳定 ID、episode 外键、唯一集内排序、地点原文、地点设定关联、内外、日夜、氛围。               |
| `script_beats`        | 稳定 ID、scene 外键、唯一场内排序、action／dialogue 判别、对应文字字段、说话人原文及关联。    |
| `scene_characters`    | 场与人物的去重关联、显示原名及顺序；对白人物必须被补入本场关联。                              |
| `story_elements`      | 稳定 ID、四种既有类别、待确认／已确认、描述、按类别校验的 attrs、手工完善标记、时间戳。       |
| `story_element_names` | 主名／别名的规范化查找键；同项目同类统一唯一，主名与别名不能跨两条元素碰撞。                  |
| `story_ignored_names` | 既有忽略／恢复行为的数据，不被重新导入立即复活。                                              |
| `script_imports`      | 原文、摘要、基准 revision、模型配置快照标识、阶段、批次结果和来源区间、错误、完成／应用标记。 |

字段和分表可在不改变上表语义的前提下合并，但不得用一份可修改的整集 JSON 再加一份可修改的分表正文。正文关系使用外键、CHECK 和唯一约束；显示排序更新必须在事务内解决临时唯一冲突。

保存文档、精确去重、关联更新、revision 增长、导入应用标记必须在同一个项目 SQLite 事务提交。模型调用在事务外执行，不能长时间持锁。跨项目同名无关；应用数据库不建立指向项目文件数据库的伪外键。

连接生命周期按项目 ID 和规范化根路径管理，路径必须沿用现有 junction／realpath 边界检查。推荐单应用写入和 SQLite 默认回滚日志模式，不为本次增加同步／多用户协作能力。关闭、重定位、从项目库移除、移到系统回收站之前释放项目连接；关库后复制整个项目再打开必须成立。缺库／损坏库不能以空库静默顶替新格式项目。正在写入时由外部同步软件复制数据库不属于可保证场景。

### 旧格式清理与格式升级

这是用户授权范围内的一次性破坏性格式升级，不是内容迁移，也不是每次启动清库。

1. 在项目第一次真正打开／升级时执行，不扫描并删除未打开的任意目录。新建项目直接使用新格式。读取旧清单只为保留项目和创作页信息，不解析、转换或恢复旧剧本。
2. 只清理 `.frameloom/scripts/`、`.frameloom/story.json`、旧清单 `episodes[]`、`.frameloom/trash/scripts/` 及能证明属于剧本的临时导入残留。不得递归清空 `.frameloom/trash/`、`.frameloom/tmp/` 或整个内部目录；`trash/pages`、`trash/media`、资产和模型配置保留。
3. 原子重写清单，解除创作页摘要里旧 `episodeId`，不改画布 JSON。旧缓存、任务和引用定位必须失效，旧路由返回明确不存在。
4. 磁盘项目格式版本升级，让旧应用明确拒绝新格式；新格式缺少项目库时必须报错，不能再触发旧格式清理。`formatVersion` 的兼容读取与 API 聚合需分开校验。
5. 文件删除和 SQLite 不是一个事务。必须用可恢复的清理阶段处理：在破坏性操作前记录待清理状态；升级期间禁止正常剧集／设定写入；所有清理和脱钩成功后才标记完成并开放写入。中断后继续剩余步骤，不能误删已创建的新数据。
6. 删除失败、清单写入失败、库创建失败均停止升级并返回可重试错误。不存在的旧文件可视为该步完成；标记缺失、库损坏不能自动解释成可反复清除。项目级 schema 后续升级与本次旧格式清理分开，禁止复用清理入口实施常规迁移。

不增加旧内容备份／恢复 UI，也不迁移手工设定；不删除用户自行保存的项目副本或应用级既有备份。当前会话不会对任何真实项目执行上述操作，实施验收先使用可丢弃的临时项目。

### 全文模型解析、分批与保真

复用现有文本模型服务和渠道管理。没有可用默认文本模型时导入报明确错误，不能降级规则解析。原文仅作为数据，提示词中的原文指令不能变成系统指令。

短文可一次返回标准 JSON。长文采用「模型定位场次边界 → 按场解析 → 程序校验和组装」，过长的边界定位输入先按容量分块；过长单场再拆内容片段。程序可以按行／段编号和容量切片，但不得用场标题正则、旧 parser 或关键词猜测正文类型。

内部批次协议必须带来源区间和续场身份：每段原文有稳定行／段编号；批次持有负责区间，附带上下文的重叠区间不能重复生成正文。边界输出要区分元信息、场次及不可表示内容；跨批同场明确连续，不能仅按地点相同合并两场。模型解析每场／片段时返回原文映射，程序按区间顺序拼接，不靠重复字符串去重。模型不能产生最终内部 ID 或决定最终场号。

检查 `contextWindow`、`maxOutput`、系统提示和已知设定占用。预算不足要继续细分或明确失败，不能沿用当前默认 1024 输出却声称支持整集。现有文本调用的 60 秒限制需要提供本次解析的有界调用选项；普通模型测试和其他调用保持现有行为。重试有上限，缩小批次也有最小单位／调用总量上限；记录实际值，不能无限递归或自动更换收费模型。可恢复的失败批次复用已验证批次，进程重启后不自动重新付费调用，由用户在重新导入流程中选择重试。

校验分层：JSON／Zod、来源区间完整且有序、场次续接一致、动作／台词／说话人／情绪的原文覆盖。允许去除 Markdown 展示符、动作标记和结构分隔符；不能用「忽略所有标点空格」掩盖台词变化。原文不是严格新模板时仍由模型识别，但无法表示的实质内容要明确失败和定位，不能悄悄丢掉或新增 sound／note 等类型。自动校验不能证明语义绝对正确，验收还要人工逐场校对。

项目／剧集权威字段和最终场号在组装时投影；模型返回不同剧名、集号、标题、时长、画风或类型时不修改项目／剧集，结果提示说明采用当前项目信息。每次应用前再读最新 revision；项目身份／模型输入相关信息变化不能用过期结果覆盖，允许重新校验或重试，不做跨集猜测匹配。

任务状态至少区分排队、模型定位／解析、校验、应用、成功、失败、取消。只对已知批次展示真实完成数，不伪造模型 token 百分比。原文和已验证批次保存在项目库；任务运行期不修改有效剧本和设定。全部成功后在短事务中提交；取消／超时／程序退出均无半份剧本。一个项目中的不同任务仍可复用现有串行调度，不增加跨项目全新调度框架。

### 设定资料、去重与引用

| 类别               | 字段                                                                                                 |
| ------------------ | ---------------------------------------------------------------------------------------------------- |
| 人物               | 姓名、别名、描述、年龄文本、性别、外貌锚点列表、性格标签列表、标志动作列表、标志道具文字列表。       |
| 地点（界面称场景） | 名称、别名、描述、空间类型、时代／地域、空间布局、视觉锚点列表、色彩与材质、标志陈设列表、补充说明。 |
| 道具／服装         | 保留已有分类、创建、资料、别名、合并、忽略／恢复能力；不新增自动全文抽取或素材绑定。                 |

场次 `atmosphere` 与地点设定分开。日夜和本场内外是场次属性，不将同一地点的昼夜创建成两个元素，也不反复覆盖地点资料。姓名／地点使用 trim 和大小写归一的精确查找键，不删除名字中间的字、括号或做拼音／繁简／语义合并；更复杂规范化不得擅自加上。

自动识别的触发点是整集模型导入：模型负责把动作中明确出现的人物补到 `characters`。普通手工输入／保存不增加隐含模型请求；出场名单和 speaker 在每次保存时同步，已有姓名／别名在动作中的出现位置由确定性匹配维护。手工编辑时新人物通过人物名单／speaker 建立；若要求每次任意动作输入都进行语义抽取，必须另行确认触发、费用和离线行为，不得由实施 Agent 悄悄扩大。

同名／别名复用元素 ID，自动新建待确认。编辑人物资料后标记手工完善，不能只依靠「已确认」状态防止清理。去掉引用只解除关系；无引用、未完善的待确认候选可沿用现有孤立清理策略，但必须跨全集计算。设定改名保留原名称为别名，内部关联不丢，正文不改。人工合并重定向关系并保留源名称为别名，双方手工资料冲突不能直接覆盖或丢弃；保留目标值并让用户选择处理源值。忽略设定不得删除正文，重复导入不复活已忽略名称。

## Alternatives considered

- **保留项目 JSON 文件**：最强理由是便于目录复制、查错和同步，现有系统无需新数据库生命周期。未采用：用户明确选择项目级 SQLite；本次正文与设定关系需要事务一致，不继续修补跨文件写入。
- **使用现有应用级 SQLite**：最强理由是复用迁移和关库流程、减少连接管理。未采用：项目复制后内容不自然随行，与用户确认的项目自包含冲突。
- **SQLite 整集 JSON 加关联投影**：最强理由是直接对应模型输出，代码更少。未采用：用户接受分表，场次、人物、内容和排序需要外键／唯一约束；不能保留两份可写正文。
- **继续模型只输出分类标签**：最强理由是输出省、保真检查简单、旧代码可复用。未采用：用户明确改为模型返回标准 JSON，并接受长文多次调用和更长耗时。容量和保真风险以分批校验承担，不能偷偷退回旧路线。
- **复制原型 contenteditable 实现**：最强理由是最快贴合 DOM 和视觉。未采用：原型没有可靠历史、保存报错和完整类型切换保护，整场重绘影响选区与输入法；现有 Tiptap 依赖可继续使用。
- **保留 Markdown 视图兼容旧习惯**：最强理由是整段粘贴和修改方便。未采用：用户明确要求移除双向编辑并严格收窄，不为旧测试继续维护第二条正文编辑路径。

## Risks

- 清除不可恢复：这是用户确认的范围，但执行前必须使用临时项目证明选择器准确；不能从用户真实项目生成测试样例。文件删除与数据库不能伪装成同一个事务。
- 输出内容较标签模式大，调用次数、费用与时延增加；各模型上下文、输出和超时不同。分批成功也不代表没有语义误解，真实语料逐场校对是必要验收。
- 纯新规范无法无损表达所有旧格式；不能靠隐藏旧字段或省略文字掩盖不兼容。无法表示时明确拒绝，用户自行调整源文。
- 项目 SQLite 新增连接关闭、格式版本和关库复制边界；不保证打开状态下同步盘复制／跨进程并发编辑，不为这些场景扩展产品范围。
- 自动识别任意新动作人物与不让普通保存依赖模型之间存在边界。导入必须完整抽取；手工新人物应通过出场名单／说话人明确建立，若用户后续要求每次动作输入都智能抽取，需单独决定触发、费用和离线行为，不能在实施中悄悄加入。
- 原型只有明亮模式，且在本轮工具环境中本地 `file:` 浏览预览被安全策略禁止；当前仅依据 HTML／CSS／脚本静态核对，未声称完成像素或原生交互验收。后续使用获准的本地预览／测试环境，不能绕过浏览器安全限制。
- 本次不默认重跑无关测试，也不要求完整 NSIS 安装流程；项目 SQLite 直接关系 Windows 文件句柄，目录版启动、退出和关闭后移动项目仍为必要验收。
