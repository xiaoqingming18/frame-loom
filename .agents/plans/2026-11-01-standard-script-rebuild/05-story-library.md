### 去重与资料验收矩阵

| 编号 | 输入／操作                                                                                   | 必须断言                                                                 |
| ---- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| S01  | 同项目 character 林夏，重复主名；别名「小夏」被另一主名占用；仅大小写／首尾空格差异          | 唯一复用或明确 409；主名与别名交叉约束，数组内重复拒绝。                 |
| S02  | 同项目 character／location 同名；另一项目也有林夏                                            | 不跨类别／项目误合并；元素与库完全隔离。                                 |
| S03  | 两集三场，地点便利店分别日／夜；林夏／别名小夏，新增动作独有人物老陈；speaker 西装男不在名单 | 便利店一条设定，林夏一条设定；老陈、西装男都有正确场关联；每场氛围独立。 |
| S04  | 重导入 S03，已有林夏 age、外貌、性格等人工资料，模型返回不同描述                             | addedElements=0，手工字段逐项相同，已有 ID 不变；不采用模型臆造 attrs。  |
| S05  | 关联插入途中故障；两任务竞争创建同名人物                                                     | 正文／关系／元素／revision 原子回滚，成功者不重复元素，失败明确。        |
| S06  | 林夏改名林晚；读旧正文，再导入仍叫林夏的下一集                                               | 旧名为别名，旧正文不变，旧引用和下一集均指向同一 ID。                    |
| S07  | 两人物各有手工资料，执行合并／取消合并；两个地点合并                                         | UI 显示冲突，关系重定向，源名可查；无隐式丢资料；取消无写入。            |
| S08  | 忽略一个人物并重导入，再主动恢复                                                             | 正文一直不改；重导入不复活；恢复可关联；无忽略名误伤另一项目。           |
| S09  | 两集都有同人，删一集引用；再删全部；随后分别测试 confirmed／手工完善 pending／未完善 pending | 有其他集引用必保留；前两种无引用保留，最后一种才清理。                   |
| S10  | 林／林夏同时出现，移场移行后点击出现位置，再删该行                                           | 不双计子串；定位同一稳定 ID；已删位置明确失效，不跳另一行。              |
| S11  | 各字段填中文和列表，保存重开；保存失败再重试                                                 | 字段和列表顺序完整，年龄可“约30岁”，错误不丢输入；无必填捏造数据。       |
| S12  | 创建／修改道具“旧钥匙”和服装“风衣”，别名／忽略／搜索                                         | 四类入口均可用；人物标志道具只是文字，不自动创建／绑定素材。             |

对动作中的人物识别，验收重点是模型导入后完整入库；普通手工编辑不额外偷偷发模型请求。手工新增人物通过出场名单／speaker 建立，已知名字在动作里的出现位置必须更新。若认为用户要求每次任意动作输入都语义抽取，先上浮决策，不用这一边界冒充已实现智能抽取。

## 发现与偏差

- 旧合并只保留目标资料并添加别名，源 attrs 可能丢失；本次必须给出冲突处理，不能仅迁表保留缺陷。
- 单独的 pending 状态不足以保护用户完善过的资料，需持久化手工编辑事实或等价信息。
