# Plan: 模型全文解析、长文分批与原文校验

Status: draft
Parent: plan.md

## 目标

实现 R10、R11、R14；短文、长篇多场和超长单场均由文本模型返回结构化内容，程序只编排与校验。失败不替换、重试有界、跨批不漏不重，满足 A04。

## 前置条件

- 01—03 的文档／批次协议、任务持久化、保存事务与 revision 检查可用。
- 阅读 `apps/engine/src/modules/scripts/{conversion.service,conversion.controller,conversion-prompt}.ts`、`apps/engine/src/modules/llm/llm.service.ts`、`apps/engine/src/testing/{test-engine,mock-upstream}.ts`、现有 conversion 集成测试与调用者。
- 不新增模型供应商或改变默认渠道；测试沿用本地 mock 上游，真实调用仅在 08 单独执行并标注实际次数。

## 步骤

- [ ] T1 删除转换入口的旧 parseScriptText／guess／decisions 分类与规则兜底；输入校验默认文本模型可用、原文非空、有效项目／剧集和基准 revision；保存原文与任务，当前正文不动 — 验证：M01、M02，请求明确包含完整原文或其有序区间，不仅送存疑行。
- [ ] T2 实现容量预算与有界调用选项，记录 contextWindow、maxOutput、提示词／上下文开销、片段上限、单次超时、重试上限及总调用上限；只对剧本路径调整，校验 finish reason／截断 — 验证：M03、M10，旧 chat/test 调用仍默认原参数；不把未知容量视作无限。
- [ ] T3 实现单次短文协议与定位／解析系统提示；原文当数据、禁止润色续写、禁止覆盖权威元信息、只返回 schema 所需字段，动作中的明确人物补进 characters — 验证：短样例逐字预期通过；原文中伪系统指令不改变输出契约。
- [ ] T4 实现长文分块定位，程序只按来源编号／容量划块并携带上下文，由模型识别场次边界和续场；区分负责区间与重叠上下文，校验完整覆盖 — 验证：M04，换一个不符合旧场标题正则的输入仍走模型；不引入本地类型猜测。
- [ ] T5 按已验证边界解析整场；超长单场再按有序片段解析并显式续场，保存每批来源映射，按源区间组装 — 验证：M05、M06，内容相同的两句均保留，两次出现同地点不能合成一场。
- [ ] T6 实现来源和保真校验：字段路径到来源位置，动作／对白／speaker／emotion 的文本覆盖与顺序；只容许明确列出的展示符／标签规范化，未知或不可表示内容定位失败 — 验证：M07，换一个标点／少一个否定词／漏一句都不能仅靠 JSON 合法放行。
- [ ] T7 对无效 JSON／容量截断进行有限修正请求或缩小片段重试，成功批次缓存按原文摘要＋模型／协议版本＋区间识别；输入改变不得复用旧批 — 验证：M08，不调用已成功批，不无限循环，不自动换模型；记录实际预算与重试次数。
- [ ] T8 接入排队、取消、超时、任务持久化和进程退出；重启把未终结任务标为可重试中断，不自动继续付费；取消后迟到回包只丢弃 — 验证：M09，每个终态状态正确，当前剧本／设定均不变。
- [ ] T9 全批校验后投影当前项目／剧集元信息并按顺序生成 scene_id，生成内部 ID，调用 03 已完成的同步核心，在同一事务更新正文、人物／地点关系和应用标记 — 验证：M11、M12；成功事件在事务提交后发布，不输出中途成功，不等待 05 的资料管理功能。
- [ ] T10 对模型返回不同剧名／集号等给出结果提示；项目输入上下文变化、基准 revision 过期、原文变化时阻止旧结果应用 — 验证：M12，不自动选择另一集，不覆盖项目字段。
- [ ] T11 写定向协议和故障集成测试；通过小容量配置强制真实分批算法，不用 mock 一个完整最终 JSON 跳过定位和拼接 — 验证：M01—M12 实际执行，测试断言请求区间、批数和最终正文，不只断言 succeeded。

### 模型／长文矩阵

| 编号 | 输入／故障                                                               | 必须断言                                                              |
| ---- | ------------------------------------------------------------------------ | --------------------------------------------------------------------- |
| M01  | 未配置模型、禁用模型、媒体模型、凭据失效                                 | 导入失败清楚，原文可保留，不调用旧规则，不改变有效文档。              |
| M02  | 短样例含 Markdown、空 emotion、动作独有人物、漏填出场名单的 speaker      | 返回标准 JSON，动作与台词逐字一致，人物关联完整。                     |
| M03  | 片段刚低于／等于／高于预算，maxOutput 小到一个最小片段也放不下           | 正确分片或明确失败，输入覆盖不变，不裁断字符串；不使用无限预算。      |
| M04  | 多场长文至少三批，场标题和第一句分别在两批，边界有上下文重叠             | 全场顺序正确，负责区间唯一，重叠不产生重复，跨批同场连上。            |
| M05  | 单场正文超过一次输出；一句对白在片段边界，人物名／括注和台词分行         | 一个场、正确的 speaker／emotion／line，跨片段无重复无遗失。           |
| M06  | 两处完全相同台词、重复动作、同地点连续两场                               | 重复原句按原文次数保留；同地点两场不合并；不用 set(string) 去重正文。 |
| M07  | 合法 JSON 但漏句、改词、乱序、补写内容、非法第三类型、不可表示的实质内容 | 返回带来源定位的校验失败，不落正式正文／设定，不静默忽略。            |
| M08  | 第二批首次坏 JSON、某批截断、重试后成功；持续失败；重试前原文变化        | 仅有限重试必要批次；已成功批次复用受摘要限制；达到上限明确失败。      |
| M09  | 排队取消、定位取消、解析取消、应用前取消；运行中关服务再重启             | 每个路径终态合理，迟到回包不写入；重启无自动外网调用，可主动重试。    |
| M10  | >60 秒的可控延迟／fake clock、上游 429／网络断开、stopReason=length      | 有界超时和截断失败；普通 LLM 默认配置不变，测试不实际等待数分钟。     |
| M11  | 所有批成功，最终设定插入或应用标记更新故障                               | 正式文档、revision、关系和任务应用标记一起 rollback；重试不重复创建。 |
| M12  | 解析中项目画风／集号变化、第二窗口保存、同任务两次应用                   | 不能过期覆盖；权威字段按约定重校验；最多一次成功应用。                |

自动保真测试必须使用人工写好的 expected 和已知丢词／重复反例，不允许用被测映射算法生成两边相同的结果。模型 mock 只提供预先写好的边界／片段响应，不执行待测拼接逻辑。

## 发现与偏差

- 当前 LLM complete 固定 60 秒，默认 maxOutput 1024；原实现只返回标签，不能直接换 prompt 就宣称满足长文。
- 整段原文覆盖检查可以发现明确遗漏／改词，不能证明角色理解完全正确；08 人工逐场核对不可省略。
- 失败结果可以保留在任务中排查，但不得作为正式文档的一部分渲染成已保存内容。
