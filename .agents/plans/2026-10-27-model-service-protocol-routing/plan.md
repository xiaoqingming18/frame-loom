# Plan: 模型服务接入契约与路由优化

Status: active
Note: ../../notes/proposed/architecture/2026-10-27-model-service-protocol-routing.md

## 目标

达到关联笔记的验收标准，修复 H3 路由与响应解析，支持明确的模型接入配置、FastAIToken 视频、素材交付和任务恢复。

方案已于 2026-10-27 获用户同意，01、02 已完成；本次用户明确授权并完成 03、04。父计划保持 active，05 仍待整体验收，不修改用户数据库或发真实收费请求。

## 范围与非目标

- 范围：`packages/contracts`、engine 的 channels/generation 及迁移、desktop 模型服务页和画布任务状态、针对性测试。
- 首批覆盖现有标准媒体协议、流光 H3／OpenAI 兼容接入、FastAIToken JSON 视频任务；FastAIToken 图片缺契约，不启用。
- 不新增任意用户脚本平台、不一次实现全部原生视频与 MJ 动作、不重做画布、不扩展 Agent 或文本／TTS 业务界面。
- 不自动重跑历史失败任务，不把本计划当作修改用户数据库或费用测试的授权。
- 本计划不替代旧[模型管理计划](../2026-10-24-model-management/plan.md)的 TTS、真实供应商及安装包整体验收；交叉测试可以引用证据，不能替旧项提前宣布完成。

## 依赖与顺序

按 01 → 02 → 03 → 04 → 05 执行，每段可形成独立逻辑提交。提交实现时同步对应笔记事实和子计划进度；整套提案全部落地并验收后才移为 implemented。中途不能将整篇提案提前标成实现完成。

环境为 Node.js 24.22.x、锁定的 pnpm 12.15.0；执行前重新检查工作区、适用 AGENTS.md、源码和迁移序号，不依赖本文冻结行号。

## 验收

各子计划给出精确可观察结果。整体至少通过 contracts／engine／canvas／desktop 的相关测试、迁移与生命周期测试、类型检查、lint、格式检查、构建、`pnpm run verify`，并完成设置页与画布明暗主题检查。

供应商联调单独记录账户权限、测试型号、模式、远端任务 ID、最终结果和费用边界，不保存凭据。只有获得实际生成授权后执行，未授权时标记未验证，不把模拟服务成功称作线上通过。供应商不可用或文档缺失项明确列入交接，不静默跳过整体验收。
