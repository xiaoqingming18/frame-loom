# Plan: 多模态模型服务配置、调用与模型演进重构

Status: active
Note: ../../notes/proposed/architecture/2026-10-27-model-service-experience-and-evolution.md

## 目标

达成关联笔记的配置体验、七型号视频、跨模态调用、新模型扩展和迁移验收标准。复用当前任务、资产、加密及文本执行基础，统一接入和有效能力。

2026-10-27 用户已确认方案并授权施工；已完成子计划 01～07，08 已完成本地扩展测试和整合回归，发现的必交付缺口、原生验证及真实联调仍待收尾，父计划继续保持 active。

## 范围与非目标

- 范围：`packages/contracts`、`apps/engine/src/modules/channels`、`apps/engine/src/modules/llm`、`apps/engine/src/modules/generation`、对象存储与数据库迁移、desktop 设置／音色／测试、canvas 视频能力及相关验证。
- 视频首批：Seedance 2.5、Seedance 2.0、Seedance 2.0 Fast、Kling 4.0、Kling 3.0、Wan 3.0、MiniMax H3；完整覆盖各接入实际支持的文生、首帧、首尾帧、多模态参考、有声输出。
- 文本、图片、TTS 统一接入与配置；保留图片语义参数、多任务、引用和既有项目资产行为。TTS 音色、测试、元数据必交付；其他音频能力逐项评估。
- 有限声明式映射、定义／接入导入、模型目录版本与历史任务兼容；不内置特定中转站模板或按站名分派。
- 非目标：本地／局域网推理、ComfyUI、权重或 GPU 管理、用户脚本、远程目录服务、插件市场、Agent 编排；特殊视频操作仅预留扩展，不开放未实现 UI。
- 删除非七型号旧视频配置及默认引用；保留历史任务和文件，在途任务必要连接延迟清理。最初文档阶段未执行数据库变更；本轮 03、04 新增功能所需增量迁移并在临时库验证，未操作用户真实数据库或发起真实收费请求。

## 依赖与顺序

关键顺序为 01 → 02 → 03，再开展 04、05；06 在设置接入稳定后完成，07 汇合所有持久化与 UI 契约，08 收尾。04 与 05 可在契约稳定后并行；并行不绕过同一文件和迁移序号协调。01～06 引入的必要 schema 变更随对应代码和增量迁移提交，07 负责升级链与清理闭环，不把前序功能放在不可运行的半成品库结构上。

每段可对应一到数次逻辑提交，实现、必要测试、笔记事实与进度同批更新。以新笔记为决定来源，旧两组模型计划的已完成步骤仅作基线；未完成验收由本计划接管，不恢复旧站点专属测试范围。

环境：Node.js 24.22.x、仓库锁定 pnpm 12.15.0；开始前检查工作区、适用 AGENTS.md、当前源码、迁移 journal、现有测试脚本及实际 UI。源码可能变化，不依赖本文冻结行号。不得改写已经分发的迁移。

## 验收

- 八个子计划各自完成步骤与验证，无草稿功能、空入口或虚构供应商能力；所有跨层调用使用相同接入与有效能力。
- 七型号／协议／渠道绑定／模式矩阵可追踪来源与验证版本，支持同模型不同协议及同渠道多接入。
- 模拟测试覆盖精确 URL、Content-Type、映射、错误、上传、重启、提交不确定、下载及取消；验证次数证明不重复提交。
- 新视频、图片、TTS 测试定义仅用现有契约接入，前端无新增型号判断；不支持的契约和能力明确拒绝。
- 旧视频配置清理不损坏历史文件、任务、默认引用或共用连接；数据库备份、失败回滚与在途恢复有临时库证据。
- 预期质量门禁：`pnpm run test`、`pnpm run typecheck`、`pnpm run lint`、`pnpm run format:check`、`pnpm run build`、`pnpm --filter @frame-loom/desktop test:e2e`、`pnpm run verify`、`git diff --check`。实现时记录实际结果，不继承旧测试数字作为新证据。
- 明暗主题、最小窗口、键盘／点击问号帮助、错误／费用状态及加固产物经过观察；自动测试不能替代必要原生桌面检查。
- 真实生成只在明确账号、型号、模式、费用范围授权后执行；未验证项逐项交接，不把某渠道或模式成功外推全部。不能因缺真实联调而伪造完成或提前将笔记转 implemented。
