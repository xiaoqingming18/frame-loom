# Plan: 模型定义、服务接入与导入契约

Status: draft
Parent: plan.md

## 目标

在共享契约中表达渠道、服务接入、模型定义和渠道绑定，提供可版本化有效能力与有限映射，供 engine 与 renderer 共用。

## 前置条件

- 用户另行要求开始实现后，将本计划与父计划转 active。
- 阅读关联笔记及 `packages/contracts/src/models.ts`、`generation.ts`、`service-routing.ts`、`image-params.ts`、`image-references.ts`；核对渠道、生成任务及画布的全部调用者。
- 使用父计划指定工具链；本轮无实现与契约测试执行。

## 步骤

- [ ] T1 定义分层对象、稳定逻辑 ID、精确版本、渠道别名和凭据引用；划定现有字段兼容边界 — 验证：contracts 样例表达同模型不同协议、同渠道多接入，拒绝跨渠道非法绑定和明文凭据导出。
- [ ] T2 从现有 ModelProfile 拆分模型能力、接入能力及运行策略，建立模式、参数、素材、声音与组合条件的共享解析／校验 — 验证：范围交集和条件组合在前后端同结果，不允许能力覆盖突破适配器边界。
- [ ] T3 定义有限映射的字段选择、嵌套、固定值、类型／枚举转换、素材角色和内置编码；设置深度、大小及数量上限 — 验证：正确样例可表达已确认差异，脚本／表达式／越界路径／无限结构和未知转换被拒绝。
- [ ] T4 定义导入包 schema／依赖版本、来源、冲突、预览差异、事务提交及验证状态；保留升级与历史解释规则 — 验证：敏感字段、未知必需版本、不支持操作、非法网络目标和能力膨胀导入失败，旧配置不受影响。
- [ ] T5 定义七型号目录与可扩展操作标识、参数帮助元数据、规范化请求／产物以及音色归属；特殊视频操作仅可声明未执行状态 — 验证：目录不硬编码成永久型号枚举，未实现操作不能提交，新定义无需改变 UI 类型。

## 发现与偏差

现有参数值主要为标量，不能通过任意 JSON 透传绕开新操作的专属输入校验。四种职责不要求机械增加四张表，落库方式在读懂现有 schema 后选最小完整方案。
