Status: draft

## 目标

按实际契约支持七个目标视频型号及兼容渠道，统一文本、图片、视频、TTS 的连接解析，移除内置站点模板和站点名称驱动的执行分派。

## 前置条件

- 01 完成，模型与接入契约稳定。
- 阅读 `apps/engine/src/modules/channels/channels.service.ts`、`apps/engine/src/modules/llm`、`apps/engine/src/modules/generation/adapters`、`profiles` 以及对应测试；复核笔记中的官方与样本 URL。
- 线上请求另需账号、具体模式与费用授权；文档及本地测试不需要收费生成。

## 步骤

- [ ] T1 建立七型号×协议×模式证据矩阵，核对上游 ID、版本、鉴权、区域、请求／响应和素材组合 — 验证：Seedance 三型号、Kling 两型号、Wan 3.0、H3 各有独立规则来源，渠道别名不等于新官方版本，未知能力明确未确认。
- [ ] T2 为所有模态建立统一有效连接解析边界，处理 SDK 前缀约定、型号路径与操作参数 — 验证：部署前缀、跨域接入、TTS 覆盖及文本 SDK 最终 URL 与预览一致，新配置无自动补删版本前缀。
- [ ] T3 补齐 Ark／MiniMax／Kling／Wan 原生契约并复用现有可用实现，按需要区分新旧协议版本 — 验证：严格本地 HTTP 服务验证方法、路径、鉴权、请求体、任务响应、业务错误、查询及下载，错误地址不会误判成功。
- [ ] T4 将已有 JSON／multipart 兼容实现整理为有明确 schema 的适配器及有限映射，清除内置中转站地址和站名判断；历史兼容单独保留 — 验证：相同契约在两个任意测试域名／前缀下运行，不将只相似的 JSON 接口混为通用标准，不改名即冒充兼容。
- [ ] T5 为七型号装配模型定义与规范化参数转换，复核文生／首帧／首尾帧／参考／声音组合 — 验证：参数不整体展开透传，素材角色和次序保持，特殊操作不因提示词猜测而被静默启用。
- [ ] T6 回归四文本协议、既有图片语义及 TTS 请求，发布能力与当前验证级别 — 验证：目录无响应不阻止手动绑定，未知协议无默认回退，文本事件／工具语义及图片编辑字段保留。

## 发现与偏差

现有 MiniMax 默认路径带中转挂载前缀，TTS 不消费模型 connection；不能把旧路径统一换成官方路径后破坏历史恢复。兼容格式不意味着官方服务当前在线；fal、Replicate 等是扩展边界样本，不自动变成本轮全部适配承诺。
