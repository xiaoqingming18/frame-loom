# Plan: 配置升级、旧视频型号退出与历史保留

Status: draft
Parent: plan.md

## 目标

将现有四类模型迁到新配置结构，删除非七型号旧视频配置与默认引用，同时保留历史任务、项目资产及在途查询／下载所需连接。

## 前置条件

- 01～06 完成，持久化字段、设置／画布引用及音频范围明确。
- 阅读 `apps/engine/src/core/database`、实际迁移目录及 journal、channels／generation schema、项目及画布模型引用。新增迁移按当前序号生成，不改写已分发迁移。
- 用户已同意旧视频配置退出及分阶段清理；本轮仅文档编写，不触碰用户数据库。升级测试使用临时数据库与测试项目。

## 步骤

- [ ] T1 建立旧字段与新对象映射，识别七型号精确版本／已确认渠道别名，展示无法判定项 — 验证：文本／图片／TTS 不误删，计费后缀和型号变体不靠子串混同，非法或未知映射不静默推断。
- [ ] T2 完成增量升级与备份恢复路径，将既有有效地址／路径和凭据归属明确迁移 — 验证：旧地址不全局补删版本，升级可重复验证，故意失败事务无部分字段或部分删除，备份可读且恢复方法明确。
- [ ] T3 清理非七型号旧视频的可新建绑定及默认引用，处理画布和历史重试入口 — 验证：旧型号不再可选／重新生成，画布原内容、连线、历史任务与资产仍可访问，失效默认值不会切到未经选择的收费模型。
- [ ] T4 为未完成远端任务保留仅恢复用途的连接／凭据引用／旧契约，终结或显式放弃后按引用回收 — 验证：查询及下载仍用旧目标，缺快照暂停不重投，多个任务或其他模态共享的连接／渠道／密钥不误删。
- [ ] T5 防止普通编辑、导入、目录更新和后台清理绕过恢复引用规则，明确未知提交与下载失败的保留策略 — 验证：跨重启仍可恢复可确定目标，用户放弃不冒称远端取消，历史资产没有级联删除。
- [ ] T6 补齐旧库升级、混合模态、在途状态及清理回归，并同步兼容层退出条件 — 验证：从旧发行 schema 到新 schema 的完整迁移链通过，清理仅发生在无有效引用时，不遗留可创建旧型号的兼容入口。

## 验证

预期运行数据库迁移、channels、generation recovery、项目资产及画布持久化相关测试，补充 Electron 升级夹具验证；再运行 `pnpm run typecheck`、`pnpm run verify`。对版本升级、失败回滚、重启及引用完整性使用真实临时 SQLite，不使用纯 Mock 声称完成迁移。

实际：未执行。未删除任何现有模型配置、任务或文件。

## 进度

## 发现与偏差

“删除配置”不等于删除历史任务与文件。未完成远端任务、未知提交和下载失败可能仍需旧凭据与解析版本；无法确定历史目标时只能暂停并提供处理入口，不能猜测或自动重新生成。
